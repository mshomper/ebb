# Tests in Node, test files found by themselves, progress entries and a type check (m2-test-tooling)

Status: Done

The Code Health findings, Matt, October 31, 2026. `node tools/run-tests.mjs` runs the unit tests in Node over the computer's cores, through the same worker the test page uses, and prints a short summary and any failures; `--affected` runs what the branch changed reaches (from `tools/affected-tests.mjs`) and the core, `--groups=` the groups named. It names the few groups that still need the browser page (the worker pool, the palette's WebGPU bake and the waterfalls) with the link to run them. A branch now runs `--affected` while it works and at handoff; the full suite runs once, on the combined tip in the merge queue. Test files are found by their names: `node tools/index-tests.mjs` writes the list (`tools/unit-tests-index.js`), and both runners stop when it is out of date, so a new test file never means editing a shared list. The pure groups that were written on the test page (rng, clock, events, store, terrain, undo, sky and seasons, tide, water summary and the smoke) have their own files. The progress table becomes this folder: one file per branch, with `tools/progress.html` to read it all in date order. `node tools/typecheck.mjs` runs the TypeScript checker on the `@ts-check` files and reports new errors against a baseline of 403. `tools/run-audio-tests.mjs` is folded into the runner.
