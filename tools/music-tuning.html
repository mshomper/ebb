Tuning the music

How often the island plays, and how to keep your changes

Everything about when music plays is in one file, recipes/music/director.json. You change numbers in it, check them in the music lab's Day tab and in the game, then save them to the repo with GitHub Desktop. No code changes are needed. This page reads the file as it is now, so the numbers below are always current.

1The short version

  1. In GitHub Desktop, check the Current branch at the top. It must not be main. If it is, choose Branch > New branch, name it, for example music-tuning, and create it.
  2. Open C:\Users\mshom\Documents\GitHub\Ebb\recipes\music\director.json in a text editor (Notepad works; VS Code is nicer).
  3. Change a number in the "frequency" block (section 3 says what each one does). Save the file.
  4. Double-click play.cmd, then open the music lab's Day tab: music-lab.html#day. Choose Pool: The game, your setting, 3 days, and read the Silence tile.
  5. Listen in the game: index.html?music=now plays a grown piece right after your first tap, then the director carries on with your numbers.
  6. Happy with it? In GitHub Desktop, write a short summary, click Commit, then Push origin (section 6).

4Changing a number safely

The file is JSON: names in double quotes, a colon, then the value, with commas between entries. Change only the number and leave the punctuation as it is. Here is "Often" with shorter rests:

"often": { "chanceScale": 1.8, "restScale": 0.28 0.2, "max": { "interlude": 12, "nocturne": 5 } },

Rules of thumb

  • More music: make restScale smaller first (shorter silences), then raise max.interlude (more pieces through the day).
  • Less music: make restScale larger, or chanceScale smaller (more slots pass by with nothing).
  • chanceScale above about 1.8 changes little, since most slot chances are already nearly certain.
  • Change one thing at a time, and read the Day tab after each change.
  • Use a dot for decimals (0.3, not 0,3), and never leave a comma after the last entry in a block.

If the game or the lab goes quiet after an edit, the file probably has a typo (a missing comma or quote). The lab's Day tab shows the error at the top. Fix it, or start again from the saved version: in GitHub Desktop, right-click director.json in the Changes list and choose Discard changes.

5Checking a change

In the music lab (quick)

  1. Open music-lab.html#day and refresh it after every save (the lab reads the file fresh each time).
  2. Choose Pool: The game. That is exactly what the island plays: the four tides, plus a new grown piece from the composer for any other slot.
  3. Choose Piece lengths: Real piece lengths, your Music setting, and 3 days.
  4. Read Silence: the share of real time with no music. Today's targets are about 45 percent at Often, 55 at Sometimes and 85 at Rarely. The rows show when each piece would play.
  5. Try a few seeds with New seed; one day alone is a small sample.

In the game (by ear)

  • index.html?music=now: a grown piece right after your first tap, then the director with your numbers.
  • index.html?day=14: a new island on summer's first day. The opening plays summer's home tide 20 to 40 seconds after your tap, then a grown piece.
  • For the real feel, leave the game alone at 1x for half an hour and listen (doc 24's hands-off hour).
  • Test links never touch your saved island.

6Saving it to the repo with GitHub Desktop

  1. Open GitHub Desktop. The Current repository should be Ebb.
  2. Check Current branch. If it says main, choose Branch > New branch first and give it a name. Your edit comes along to the new branch.
  3. The Changes list on the left shows recipes/music/director.json. Click it to see your change: red lines are what was there, green lines are what you wrote.
  4. Make sure only the files you meant to change are ticked.
  5. At the bottom left, write a summary, for example Music: shorter rests at Often, and click Commit to your branch.
  6. Click Push origin at the top (or Publish branch the first time).
  7. Click Create Pull Request, then merge it on GitHub when you're happy, the same way as the other branches.

Tuning can also ride along with the audio branch while it is open: with m2-audio-ingame chosen, your edit goes into the same pull request.
